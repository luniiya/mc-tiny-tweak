# Development

Use JDK 21. Open this folder as a Gradle project in IntelliJ IDEA.

From this folder:

```sh
./gradlew :1.21.11:test
./gradlew :1.21.11:build
./gradlew :1.21.11:runClient
```

The build runs unit tests and produces the mod in `versions/1.21.11/build/libs/`.
Install the main JAR, without `-sources` in its name.

## Prism Launcher

Create a dedicated Minecraft 1.21.11 instance in Prism and install Fabric Loader
0.19.5 or newer. Add Fabric API for 1.21.11, Fabric Language Kotlin
1.14.2+kotlin.2.4.21 or newer, and the built mod JAR through the instance's Mods
page. Start with a test world. Rebuild and replace the JAR when testing a change.
The `runClient` task starts a separate development instance with dependencies
already loaded, so it is faster for day-to-day coding.

## Personal default options

`src/main/resources/mc_tiny_tweak/default-options.txt` is the reference
options.txt. On a fresh game with no options.txt, the mod writes it before the
game loads settings. Its `key_` lines also replace each keybind's built-in
default, so Reset in Controls restores these binds. Edit the file and rebuild to
change a setting or bind permanently. FOV is stored as (fov - 70) / 40.

To see the defaults in the dev client, delete `versions/1.21.11/run/options.txt`.

## Reloading

Use the Minecraft Client debug profile generated by Loom in IntelliJ for JVM
hot swapping. Recompile after editing a method body and reload changed classes
when the IDE prompts. Standard hot swapping has limits: field and method
structure changes generally require a restart. Restart after changing mixin
targets, injection structure, entrypoints, or registrations.

In the running client, F3+T reloads resource packs, including textures and
translations. `/reload` reloads server data packs. Neither reloads JVM classes.
Prism launches the built JAR normally; installing a replacement JAR requires
restarting that instance.

## Minecraft versions

Stonecutter keeps shared Kotlin, Java, resources, and tests in `src/`. Only
1.21.11 is supported initially. Add another target in `settings.gradle.kts`,
put its dependency properties in `versions/<version>/gradle.properties`, and
add it to the CI matrix. Each target gets its own build and tests.

Use Stonecutter's version conditions only around code that differs between
versions. Keep Minecraft-independent logic shared and put integration differences
in small helpers and mixins. Do not copy the entire source tree or create one
maintenance branch per game version.

Update the build script and JDK configuration as needed when adding a newer
target. Minecraft 26.1 changed mappings and Loom requirements, so adding it needs
more than a dependency bump. Support is declared only after the target builds,
its tests pass, and the relevant gameplay has been tested. JAR filenames include
the Minecraft target; the mod metadata currently permits exactly that version.

## Tests

Always add unit tests for changed logic and regression tests for fixes. Fabric
Loader JUnit runs tests with the loader environment. Keep pure logic independent
of Minecraft when possible. The initial tests verify loading metadata, Kotlin
entrypoint resolution, and packaged mixin configuration. Tests that need items
or registries call `MinecraftTestSupport`, which bootstraps vanilla and builds
the vanilla registry lookup.

Add server or client GameTests with the first gameplay feature that needs them.
GameTests and a real client smoke test are needed to validate actual injections;
passing unit tests alone does not prove a mixin works in game.

## Item editor

Press `\` in game to open the mod menu (rebindable under Controls, MC Tiny
Tweak). The item editor edits the held item. Apply (Creative) uses the creative
inventory packet, which servers only accept in creative mode. Apply (OP) sends
`/item replace entity @s hotbar.N with ...` (built by `ItemCommand`), which
works in any game mode with permission level 2.
Logic lives in `itemeditor/` and is unit tested; screens live in
`client/itemeditor/`. `ItemDraft` applies edits on top of the held stack and
keeps every component it does not edit. The raw editor reads and writes the
whole stack as SNBT through `ItemStack.CODEC`.

Creative Editor (https://github.com/Ruukas97/Creative-Editor) is the feature
reference. It is GPL-3.0, so its code is not copied here.

Readable Minecraft source for reference comes from
`./gradlew :1.21.11:genSources`. Keep decompiled source and other material
that must not be published outside this repository.

## Key Binds screen

The Controls > Key Binds screen gets a key search (click it, then press a key or mouse button; Escape clears), a name or category search, a Tablet/Mouse toggle for attack, use and freelook (tablet: Q, E, hold left click; mouse: left click, right click, hold middle click), "Unbind extras" (unbinds every bind not listed in `default-options.txt`), and "View defaults" (a read-only list of the bundled binds). `KeyBindsScreen` inherits `addTitle`, so `KeyBindsScreenMixin` overrides it rather than injecting into it.

## Freelook

Hold the freelook key (middle click by default, with pick block moved to P; sprint is on Z in the personal defaults) to look around while the player keeps facing and moving the same way. First person switches to the back view while held and returns on release. `FreelookCamera` holds the tested logic. `MouseHandlerMixin` sends mouse movement to it instead of the player, and `CameraMixin` points the camera along it. Written from scratch with Celibistrial's AGPL Freelook mod as a behavior reference only.

## Freecam

Freecam (F7, or Mod menu > Freecam) flies the view away from the player. It is on while the toggle is on or an
agent has taken over, and off only when both are off. While an agent plays, R swaps between the freecam and the
agent's eyes, and a tooltip-style card in the top right shows the agent's last tool call, Baritone process, health
and food. Freecam hides the hand, crosshair, hotbar and the player's bars; agent view shows them. Movement reads the
physical keys (`InputConstants.isKeyDown`), because key mappings are blocked while freecam holds the player's input.
`CameraFreecamMixin` moves the camera at the end of `Camera.setup` and marks it detached so the body renders.
Agent screenshots show the agent's eyes for two frames unless they pass `view: "player"`.

## Crafting tool

`craft` (needs take over) finds an unlocked recipe-book entry for the item that fits the open grid (2x2 inventory,
3x3 crafting table), sends `handlePlaceRecipe`, then shift-clicks the result slot, once per `times`. Baritone cannot
craft, so this fills the gap for agents getting tools.

## Baritone settings

Mod menu > MCP > Baritone settings lists every Baritone setting with search. `mc_tiny_tweak/baritone-defaults.txt`
holds the mod's own Baritone defaults (freeLook off, so the player looks where it goes). Each line is applied once per instance, including lines added later (marker file in the config folder), and all again by
Reset. Agents use `baritone_settings`, `baritone_set_setting` and `baritone_reset_settings`, without take over.
On/off settings only accept true or false, since Baritone reads anything else as false.

## Visual tweaks

The burning overlay sits lower (`FireOverlay.EXTRA_DROP`) and shields held in first person render at 60% opacity (`ShieldOpacity.OPACITY`); tune either constant. Shields share the banner pattern code with banners, so `ShieldSpecialRendererMixin` flags a held shield while it submits and `BannerRendererMixin` only fades layers while that flag is set.

## Tweaks and armor bar

The mod menu has a Tweaks screen. Its settings are saved in `config/mc_tiny_tweak.properties` (`TweakSettings`). Show armor is off by default: players render without armor, and a thin gray experience-bar style bar above their name fills one of four segments per worn piece in the material's color (`ArmorBar` picks colors, `ArmorBarShape` lays out the rectangles).

To test with two players, run `./gradlew :1.21.11:runServer` (offline mode, in `run-server/`), then `runClient --args="--quickPlayMultiplayer localhost"` so it joins by itself (plain `runClient` stays on the title screen). Run `runClient2` as well: it starts as Tester2 in `run-client2/` and joins localhost by itself. Running the server means agreeing to the Minecraft EULA in `run-server/eula.txt`. `runClient` always plays as Player1, so operator status and player data stay the same across launches. To make a player an operator, add it to `run-server/ops.json` while the server is stopped (the server rewrites the file on stop), or enable RCON in `run-server/server.properties` bound to 127.0.0.1 and send `op <name>`.

## Hotbar

The hotbar is split in two: slots 1-4 (X C V B in the personal binds) are separated from slots 5-9 by a gap (`HotbarLayout.GAP`). `GuiMixin` replaces `Gui.renderItemHotbar`, which is rebuilt from the vanilla sprites, so resource packs still apply. When one of those slots is empty it shows a faint shadow of its purpose (`HotbarHints`): an axe, a pickaxe, a water bucket, then a block. The first three are vanilla item textures multiplied by a translucent black, and the block is a 16x16 cube drawn from a mask.

## MCP server

The mod runs a Model Context Protocol server so an AI agent on this computer can play the game. It is on by default in every instance and has its own MCP screen in the mod menu: a main switch, one switch per kind of access (game state, screenshots, read chat, send chat, commands, movement and keys, Baritone), "Copy setup command" and "New token". Settings are saved per instance in `config/mc_tiny_tweak_mcp.properties`, and the token in `config/mc_tiny_tweak_mcp_token.txt`.

- Transport: Streamable HTTP with plain JSON replies on `http://127.0.0.1:25599/mcp`. When the port is taken (for example by a second client), the next free one up to 25608 is used; the MCP screen shows the actual one. `McpHttpServer` is written on sockets because the JDK's httpserver module is missing from some game runtimes.
- Security: loopback only, a bearer token on every request, and requests with a foreign `Origin` or `Host` are refused so web pages cannot reach it.
- Connect Claude Code with the copied command, which looks like `claude mcp add --transport http minecraft http://127.0.0.1:25599/mcp --header "Authorization: Bearer <token>"`.
- Tools (`GameTools`): `get_state`, `get_inventory`, `screenshot`, `read_chat`, `send_chat`, `run_command` (returns the chat feedback), `hold_keys`, `press_key`, `release_keys`, `look`, `look_at`, `select_slot`, `close_screen`, `baritone`, `baritone_status`, `take_over`, `release_control`, `list_servers`, `join_server`, `list_worlds`, `open_world` and `leave_world`. The world tools also work from the title screen. Switched off features drop their tools from `tools/list`.
- Take over (`AgentControl`): the agent gets sole control. `KeyMappingControlMixin` drops real key and mouse button events (except the mod menu key) and `MouseHandlerControlMixin` stops mouse turning and hotbar scrolling. The player takes control back with Mod menu > MCP > Control; `release_control` does the same from the agent and also stops held keys and Baritone. `send_chat`, `baritone`, `join_server`, `open_world` and `leave_world` need take over; `run_command` works either way.
- Every tool call is echoed in chat as a mod notice ("Show agent actions", on by default). All mod notices go through `Notices`: a pink `[MC Tiny Tweak]` tag and light pink text (`NoticeStyle`). They are left out of the agent's chat log.
- Game work runs on the client thread; waits happen on the request thread. `ChatComponentMixin` records every chat line, `KeyMappingAccessor` queues single presses, and `GameRendererMixin` stops the unfocused window from opening the pause menu while the agent is playing (holding keys or input in the last five minutes).
- Baritone is optional: `modCompileOnly` against Baritone's API, and `BaritoneBridge` only touches it when the `baritone` mod is loaded. Dev runs include Baritone 1.17.0 (the 1.21.11 build) from its GitHub release, plus its nether pathfinder, which Baritone nests and dev runs do not load.

To try it by hand, see the JSON-RPC calls in `McpProtocolTest`; `initialize`, `tools/list` and `tools/call` are plain POSTs.
